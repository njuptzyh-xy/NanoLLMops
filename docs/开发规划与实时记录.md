## 1. 项目目标

围绕 `nanoGPT` 与 `nano-vllm` 打造一个轻量级训推一体化平台，长期目标是把两者的优势能力逐步整合进同一条可维护、可验证、可持续优化的链路中。当前优先完成以下最小闭环：

```text
数据准备 -> 训练 -> checkpoint/config/tokenizer 产物固化
-> 权重转换 -> 推理加载 -> 文本生成 -> 指标采集
```

当前阶段不追求工业级平台，而是优先把核心链路做实，并保持源码清晰、可解释、可扩展。

目标澄清：

- `nanoGPT` 主要承担训练侧参考，包括训练循环、checkpoint 结构、轻量 GPT 实验路径
- `nano-vllm` 主要承担推理侧参考，包括 scheduler、KV cache、分阶段执行与高吞吐运行时设计
- `NanoLLMOps` 的长期方向不是替代两者，而是把二者结合起来，并在真实闭环中持续验证和优化
- 因此，某一阶段如果先落地最小推理链路或 vLLM-style runtime，只代表阶段实现策略，不代表放弃最初的 `nanoGPT + nano-vllm` 结合目标

## 7. 风险与关键决策

P0 风险：

- `nanoGPT` 与 `nano-vllm` 的模型结构未天然对齐
- `nano-vllm` 当前主模型实现不是 GPT-2/nanoGPT 风格
- char-level tokenizer 与推理 tokenizer 兼容路径需要单独处理

P0 决策：

- MVP 从 `shakespeare_char` 小模型起步
- 先支持单模型单请求
- 先做文件级 registry，不急着上数据库复杂 schema
- 推理 API 放到 Phase 2，Phase 1 先以 Python/CLI 为主
