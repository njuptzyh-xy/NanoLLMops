# TASK-DOC-001：开发文档分层重构

时间：2026-06-02 20:03

## 任务目标

将开发规划和开发日志分开，避免规划文件持续追加流水内容后难以快速领取任务。

## 背景

原 `docs/开发规划与实时记录.md` 同时承担以下职责：

- 项目规划
- 当前状态摘要
- 历史开发日志
- 阶段判断
- Git 推送故障记录

随着开发推进，单文件已经过长。Codex 在开始新任务时需要从大量历史内容中识别当前任务，规划入口不够清晰。

## 处理逻辑

1. 将原混合文档原样移动到 `docs/logs/`，保留全部历史记录。
2. 新建 `docs/开发规划.md`，只维护任务编号、状态、交付目标和日志链接。
3. 新建 `docs/文档索引.md`，明确开发前阅读顺序和文档职责。
4. 更新 `AGENTS.md`，要求后续开发按任务编号领取任务，并将详细日志写入 `docs/logs/`。
5. 更新 `README.md` 中的开发文档入口。

## 实际改动

- 新增 `docs/开发规划.md`
- 新增 `docs/文档索引.md`
- 新增 `docs/logs/TASK-DOC-001_2026-06-02-2003_开发文档分层重构.md`
- 移动 `docs/开发规划与实时记录.md`
  到 `docs/logs/TASK-HIST-001_2026-06-02-2003_历史开发记录归档.md`
- 更新 `AGENTS.md`
- 更新 `README.md`

## 验证方式

- 执行 `rg --files docs | sort`，检查文档布局。
- 执行 `rg -n '开发规划与实时记录|docs/logs|docs/开发规划.md' AGENTS.md README.md docs`，检查引用。
- 执行 `git diff --check`，检查文档格式。

验证结果：

- `docs/logs/` 已包含当前任务日志和历史归档日志。
- 旧 `docs/开发规划与实时记录.md` 只在归档说明中出现，不再作为活跃开发入口。
- `docs/开发规划.md` 当前为 `59` 行，只维护阶段、任务状态和日志链接。
- `git diff --check` 通过。

## 当前结论

- 开发规划和详细日志已经拆分。
- 后续 Codex 应从 `docs/开发规划.md` 领取当前任务。
- 后续每个任务必须在 `docs/logs/` 中创建带任务编号和时间戳的独立日志。
